# 汉化参考策略

## 1. 对象分类

| 对象 | 判断重点 | 风险 |
|---|---|---|
| 字体 | 字符覆盖、fallback、字形尺寸与渲染器支持 | 缺字、乱码、裁切、布局溢出 |
| 文本 | 资源表、脚本、二进制或运行时生成来源 | 编码损坏、占位符/控制字符丢失、重复覆盖 |
| 图片文字 | 可见文字是否烘焙在纹理或九宫格资源中 | 拉伸、透明通道、边界或尺寸不兼容 |
| 语言选择 | 目标语言、默认语言与动态生成入口 | 选择被重置、残余标签或无法切回 |

## 2. 质量边界

- 先确认文本来源和渲染链，再选择字体、替换或运行时方案；不以单次截图代替来源确认。
- 翻译必须保留格式占位符、变量、转义序列、标记、参数顺序与控制语义；语义不确定时保留原文并记录待确认项。
- 字体覆盖要以实际显示字符集和 fallback 行为为准；文件存在或加载成功不能证明中文可显示，也不能替代对字形尺寸、行高和换行的检查。
- 替换图片时，保持原资源的格式、尺寸、透明信息、压缩特性和资源引用契约；文字重绘后的可读性不得以破坏布局为代价。
- 动态文本、动态语言菜单与资源加密场景均由 type workflow 的专属策略处理。

## 3. 动态页面复验

- 覆盖页面首次进入、退出后重进、页面重建以及与文本有关的状态变化；静态页面正常不能证明动态来源已经覆盖。
- 对语言选择和 fallback 的结论，应在切换、恢复默认或重新加载后复验，确认不会出现残余原文、乱码或混合语言。
- 发现只在特定引擎资源、缓存或运行时机制中复现的问题时，记录到对应 type 的经验库，不在本 skill 泛化实现方式。

## 4. 验收关注点

- 目标语言在启动、菜单、核心玩法和关键弹窗中可读，无缺字、乱码、裁切或异常换行。
- 文本替换不破坏变量显示、数值格式、富文本、控制流程或语言切换后的显示一致性。
- 图片文字替换后格式、透明和布局正常；字体替换后核心页面无渲染错误，并且没有因字形度量变化导致的重叠或截断。
- 验收设备、截图、OCR、构建和回归路径以当前 type workflow 为准。

## 5. 经验归属

- 引擎专属资源格式、解密或渲染器限制：对应 type `experiences.md`。
- 汉化领域跨 type 经验：[experiences.md](./experiences.md)。
- 项目事实、翻译表和验收材料：`crackings/<type>/<Name>/`。
