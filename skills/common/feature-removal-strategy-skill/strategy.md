# 去功能点参考策略

## 1. 判定原则

目标是移除不影响核心玩法可玩性的冗余入口、跳转和阻塞性弹窗。先确认功能在启动、菜单、关卡、奖励、存档与设置中的依赖，再决定保留、隐藏、桩化或移除。

| 决策 | 适用条件 | 记录要求 |
|---|---|---|
| 保留 | 移除会破坏关卡、进度、角色、必要设置或离线可玩性 | 说明核心依赖与保留原因 |
| 隐藏入口 | 功能可选，且不存在必须完成的前置逻辑 | 同时确认布局不留无效空白 |
| 桩化跳转/展示 | 调用方仍有依赖，但目标功能无需保留 | 记录安全返回值、回调与调用链 |
| 移除实现 | 静态资源或组件无调用方，且依赖已复核 | 记录被移除对象及依赖检查证据 |

实际方案结合 [各 type 实现要点](references/engine-notes.md) 选择，脚本由当前 type workflow 的注册表路由。

## 2. 功能分类

以下是分类摘要；执行时逐项核查 [完整清单](references/feature-removal-checklist.md)，不能只按类别粗略检查。清单条目通过管理脚本维护 YAML，Markdown 随之生成。

| 类别 | 常见表现 | 判断重点 |
|---|---|---|
| 推广与外链 | 更多游戏、联系我们、鸣谢、分享、隐私链接 | 是否只发起外部跳转；是否与合规或首启流程耦合 |
| 联网与账户 | 排行榜、社交登录、账户删除、账号标识 | 离线时是否仍可进入核心玩法；是否影响存档或身份状态 |
| 商业化入口 | 广告、订阅、恢复购买、VIP、付费引导、礼品入口 | 奖励、皮肤、角色或进度是否属于核心玩法 |
| 品牌与辅助 UI | 游戏名、Logo、版本、头像、输入框、VR/帮助入口 | 是否承载设置、状态或其他可达功能 |
| 弹窗与权限 | 同意、评分、更新、通知、广告、订阅、新手引导 | 是否阻断启动/主流程；关闭或跳过后的状态与回调 |
| 语言选择 | 语言 Tab、国旗、语言菜单 | 语言选项是否动态生成；保留目标语言后是否仍有布局残留 |

## 3. 依赖判断

对每个候选点建立最小证据链：入口/节点、触发方、目标方法或页面、返回后的状态变化、关联布局或资源。动态生成 UI 还要确认生成源，而不是只处理一次渲染结果。

以下情况需要提高风险等级并交由 type workflow 的专属流程处理：

- 调用跨越 Java/JNI/native、引擎脚本或运行时反射边界；
- 功能与奖励、购买、存档、登录状态或首启同意状态共用回调；
- UI 由列表、模板或运行时数据反复生成；
- 目标为启动页、系统栏、权限或引擎品牌资源。

## 4. 验收关注点

- 入口不可见且不可达；布局、导航与目标语言页没有空白或残留节点。
- 受影响的启动、菜单、关卡与核心玩法路径仍可完成。
- 对弹窗或跳转的处理不会造成循环、卡死、异常回调或离线阻断。
- 验收证据形式、构建与真机操作以当前 type workflow 为准。
